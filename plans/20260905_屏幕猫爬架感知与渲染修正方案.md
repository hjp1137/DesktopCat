## 已确认的问题

1. 启动版本不一致：run_desktop_cat.bat 调用 build/DesktopCat.exe。
   同目录 DesktopCat.pck 仍包含旧实现，--path . 未使测试改为读取全部当前源码。
   两组集成测试在原目录共失败 8 项，在无 PCK 的临时引擎目录全部通过。
2. TemporalFilter.update 新表面未计入本帧已匹配集合，却立即进入 missing 分支。
   0.70 置信度经 0.8 倍和 0.25 扣减变为 0.31，低于输出阈值 0.4。
3. compile_work_area_if_changed 跳过静止画面时，也跳过确认、消失计时和坐标收敛。
   已复现首帧纯视觉文本为 0 条平台，随后静止帧不再计算。
   已复现删除文本后旧平台仍存在，下一空白帧被跳过。
4. UIA 按 22 * scale_y 固定间距切割 Text/Document/Edit，不读取真实文字行。
   文本容器留白也会生成整宽踏板，字体、缩放和真实换行无法保证对齐。
5. Hybrid 视觉平台取轮廓顶沿，UIA Text 平台取控件底沿。
   同一文字最小场景同时生成 y=29 和 y=50 两条平台。
6. _extract_t25_candidates 将所有 WALL 转为 LEFT，右侧攀爬方向丢失。
7. F7/F9 仅切换绘制，update_mouse_passthrough 仍提交小猫自身多边形。
   结合既有 Windows 区域裁剪问题，当前代码没有解决全屏调试绘制与点击穿透共存。
   本轮没有执行 Windows GUI 验收，具体裁剪效果仍需实机验证。
8. Hybrid 接入后旧融合器的窗口遮挡提取不再使用；Hybrid 注入窗口边界未做 Z 序裁剪。
   原始窗口边界与实际可见边界不能等同，应补充重叠窗口场景。
9. update_cat_metrics 虽有定义，运行服务没有同步调用；当前猫尺度没有形成运行闭环。

## 推荐实施顺序

### 第一步：统一运行版本并修复生命周期

- 开发入口使用不带导出 PCK 的引擎读取源码；交付入口重新生成 PCK 后验证。
- 修正新表面本帧计数。高可信结构和纯视觉候选采用明确的确认规则。
- 将图像提取与时序追踪分开：画面未变时复用候选，追踪仍按采样时刻推进。
- 删除用实际经过时间判断；明确画面切换、服务重连和目标屏幕切换后的重置与重发。
- 在既有测试内加入静止首帧、文字删除后静止、单帧噪声及慢速移动测试。

### 第二步：统一文字和图像的物理含义

- 建议文字以可见笔画上沿为单向平台，小猫从上方落在文字上；不同时保留底沿副本。
- UIA 可取得真实行矩形时辅助定位，否则复用视觉文字行检测；禁止按固定行高造行。
- 行内只连通小字间隙，不跨栏、段落或图像空白合并；图像内部纹理不生成踏板。
- 图像与窗口保留顶边和左右侧边，携带侧向与所属窗口，按可见区域裁剪。
- 同步实际 CatMetrics，沿用当前唯一 SurfaceWorldModel 和导航重建信号。
- 验收实际脚底与内容接触误差；不能只比较表面数量或碎片压缩比。

### 第三步：解决展示与输入的取舍

- 方案 A，推荐首阶段：纯桌宠保持身体区域交互；调试使用独立普通窗口显示截图与实际融合后的表面。
  优点是实现范围小、便于核对落脚误差；代价是线条不常驻实际桌面。
- 方案 B，如需常驻发光猫爬架：增加独立透明、不可激活、鼠标穿透的调试窗口。
  小猫窗口只负责小猫交互，调试窗口负责线条；需验证多屏、DPI、拖拽与窗口叠放。
- 不恢复把全屏线条缝入小猫输入多边形的做法；也不靠清空穿透多边形满足显示要求。
- 屏幕抓取需验证是否包含自身小猫/调试层；若包含，必须排除自身窗口避免反馈生成平台。

## 验收标准

- 当前源码与交付包分别通过既有测试及新增真实失败场景。
- 静止文字可生成踏板；文字删除后按约定失效时限清除，不要求用户继续滚动。
- 同一文字行仅有一层平台，空白不造台阶；图片左右侧均可从正确方向附着。
- 实测滚动、重叠窗口、缩放及切屏；记录接触误差、更新延迟、误检和漏检。
- Windows 实机自动化截图保存到本任务 screenshots 目录；合成图不标记成真实应用截图。
- 先完成感知和显示验收，再调整自主探索偏好，避免小猫更积极地追逐错误平台。
